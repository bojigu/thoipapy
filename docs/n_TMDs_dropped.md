# The n_TMDs feature was dropped in 2.0.0

`n_TMDs`, the number of transmembrane domains in the protein, was one of the model's 27 features.
It is no longer computed, no longer part of the feature set, and has been removed from the
training data. The model ships retrained on the remaining 26 features.

## It was not working

Computing `n_TMDs` requires [Phobius](http://phobius.sbc.su.se/data.html). Phobius is licensed
academic software: it is not redistributable, is in no package repository, and cannot be installed
from apt or conda or included in a container image. In practice it was never installed, including
in the THOIPA webserver's own Dockerfile.

Its absence was not detected. `features/phobius.py` invoked it as:

```python
exect_str = "phobius {}> {}".format(full_seq_fasta_file, phobius_outfile)
```

The shell creates the redirect target before it resolves `phobius`, so a missing binary still left
a zero-byte output file behind. The code then tested `os.path.exists(phobius_outfile)`, found the
file, matched no `TRANSMEM` lines in it, and returned the counter's initial value of 1.

So `n_TMDs` was 1 for every protein, in every standalone prediction, indistinguishable from a real
measurement. `utils.Command` compounded this by discarding subprocess return codes, which is fixed
separately; it now records `returncode` and `timed_out` and exposes `succeeded()`.

## Removing it does not cost accuracy

Measured under protein-grouped 10-fold cross-validation on set08, averaged over 5 seeds, using the
model's own tuned hyperparameters:

| feature set | AUC |
|---|---|
| 27 features, `n_TMDs` correctly measured | 0.6002 +/- 0.0110 |
| 27 features, `n_TMDs` constant at 1, as actually served | 0.6032 +/- 0.0085 |
| 26 features, `n_TMDs` removed | 0.6096 +/- 0.0070 |

The differences are within about one standard deviation, so the useful reading is that removing
the feature costs nothing rather than that it helps.

There is also a plausible risk of information bleed-through. `n_TMDs` is constant within a protein
and takes only four values, so across 40 training proteins it can act as a coarse protein-identity
label rather than as residue-level evidence. That would inflate its apparent importance under
residue-level cross-validation while contributing nothing to the actual task, which is
discriminating between residues of the same helix. This was not the main reason for removing it,
but it is consistent with the numbers above.

## Consequences

Predictions from 2.0.0 differ from 1.2.0. Stored output should be regenerated. The THOIPA
webserver caches results by sequence hash with no model version in the key, so that cache must be
cleared when upgrading.

`n_homologues` is the remaining feature that is constant within a protein. Dropping it as well
scored 0.6087 +/- 0.0053, indistinguishable from the numbers above, so it was left in place rather
than changed without a reason.

## What changed in the code

- `features/phobius.py` deleted.
- `n_TMDs`, `perl_dir`, `phobius_dir` and `phobius_outfile` removed from `combine_features.py`,
  `predict.py`, `artefacts.py` and `run.py`.
- `n_TMDs` removed from `ML_model/model_features.txt` and `setting/model_features.csv`.
- The column dropped from the DVC-tracked training tables, the per-protein feature files, and the
  set07 prediction artefacts.
- Model retrained through `train_machine_learning_model` with the existing tuned parameters.
  `max_features` is unaffected: it is `sqrt`, and both `sqrt(27)` and `sqrt(26)` floor to 5.
- Golden regression references regenerated.

The per-protein feature files were edited to drop the column rather than regenerated by re-running
the feature pipeline over all 40 proteins. This is equivalent, since `n_TMDs` was written in one
place and read nowhere else, and it avoids conflating the change with several years of drift in
freecontact, cd-hit and rate4site.
